**日期：** 2026-10-08  
**负责人：** A（基础架构与接口）

## 1. 目标与边界

本阶段在现有单体仓库中新增微信原生 TypeScript 小程序工程 `miniapp/`，为后续院校、专业、规划与个人中心页面提供稳定基础。视觉严格参考老板提供的样板：绿色品牌体系、白色卡片、克制阴影、清晰层级和移动端安全区适配；内容必须来自真实接口，不把样板中的院校、用户或订单数据写死。

负责人 A 的第一阶段交付包括：

- 微信原生小程序工程与四个 Tab：`首页`、`院校`、`U圈`、`我的`。
- 统一设计变量、基础组件、加载/空白/失败/重试状态。
- 开发、测试、生产环境配置和统一 HTTPS 请求层。
- 微信小程序登录、短期访问令牌、刷新令牌轮换和退出。
- 首页骨架及一条真实院校查询链路，用于证明小程序可访问现有 API。
- 纯逻辑自动测试、类型检查、Lint 和微信开发者工具人工验收说明。

本阶段不实现：

- “我的订单”“申请详情”、材料上传、申请费用和录取进度。这些依赖尚不存在的申请业务模型，进入第二阶段单独设计。
- AI 规划和签证查询业务。首页保留与样板一致的入口，点击后显示明确的“功能建设中”，且不收集任何资料。
- U圈的帖子流、发帖、评论、点赞、举报和审核业务。U圈预计服务超过 2,000 名学生，必须作为独立子系统设计；第一阶段只交付可导航的真实登录态入口和稳定接口边界。
- 完整院校、专业、规划及个人中心业务页面；B、C 在本基础工程之上并行实现。
- 邮箱绑定 UI。第一阶段保留后端扩展点，后续由用户主动确认绑定，绝不按邮箱或昵称自动合并账号。

## 2. 已选方案与替代方案

采用微信原生小程序（WXML、WXSS、TypeScript），放在现有仓库的 `miniapp/` 目录。相比 Taro 或 uni-app，原生方案在只面向微信的前提下依赖更少、审核路径更直接，也更容易精确还原样板。

采用现有 Spring Boot 模块化单体后端，不创建新微服务。公开院校与专业数据继续使用现有 `/api/v1/**`；只有小程序身份交换和令牌生命周期使用新的 `/api/v1/miniapp/auth/**` 边界。

不采用网页 Cookie Session。小程序使用可撤销的短期不透明访问令牌与轮换刷新令牌，因为微信请求环境的 Cookie 行为不适合作为主认证契约。令牌只是随机凭证，不承载可被客户端信任的角色或个人资料。

不采用本地永久业务数据。收藏、规划和咨询记录最终全部以 PostgreSQL 为准；手机本地只保存不透明令牌、非敏感界面偏好和可丢弃缓存。

## 4. 视觉系统

样板是视觉真源，现有官网品牌变量是颜色真源。UI Pro Max 的通用蓝色教育方案与洋豆角品牌不匹配，因此不采用其调色板；仅采用其已验证的移动端触控、安全区、清晰层级和渐进披露规则。

核心颜色：

| 语义 | 颜色 |
| --- | --- |
| 品牌绿 | `#3f8875` |
| 主操作绿 | `#286858` |
| 深绿文字 | `#153f36` |
| 页面底色 | `#fdfcf8` |
| 浅绿背景 | `#eef5f1` |
| 主文字 | `#18302b` |
| 次文字 | `#536a63` |
| 分隔线 | `#c8d9d2` |
| 警告 | `#d97706` |
| 错误 | `#9f2f2f` |

字体使用微信与系统中文字体栈：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`，不加载远程 Google Font。设计以 `750rpx` 为基准；普通正文不小于 `28rpx`，辅助文字不小于 `24rpx`，主要触控区域不小于 `88rpx × 88rpx`，相邻触控区域至少保留 `16rpx` 间距。

卡片使用白色或接近白色背景、`20–28rpx` 圆角、低强度绿色阴影。动效只用于状态过渡和页面进入，持续约 200–300ms；不得依赖动效传递唯一信息。底部 Tab、固定操作区和自定义导航必须同时适配 `safeArea` 与胶囊按钮区域。

图标使用统一 SVG/图标字体资源，不使用 Emoji。图片通过后端返回的 HTTPS URL 按需加载，设置固定宽高、占位图和失败回退，避免累计布局偏移和小程序包体膨胀。

最终样板范围解释如下：

- 保留首页、院校列表、院校详情、专业详情及其资料标签、留学规划、新版“我的”、“我的订单”列表和“会员积分”列表的视觉方向。
- 两张总览图中被红色涂满的旧版“我的”页面不采用，以新版“我的”页面替代。
- 被红色涂满的“申请详情”页面不实现；不能从“我的订单”伪造跳转到不存在的详情数据。
- “我的订单”和“会员积分”依赖真实业务模型，当前阶段只确定后续导航与视觉契约，不写死样板中的申请、余额或积分数据。

第一阶段注册四个 Tab：

1. **首页**：品牌、资讯主视觉、搜索入口、规划/AI 规划/院校/签证四个功能入口、热门院校骨架。
2. **院校**：先提供可打开的列表骨架，并连通真实院校搜索接口；完整筛选与详情由 B 负责。
3. **U圈**：提供登录态入口、统一加载/空/失败状态和独立服务边界；正式社区另立规格，按 2,000+ 学生规模设计游标分页、内容审核、举报、限流和运维指标。
4. **我的**：展示登录状态、默认头像和账号入口；收藏、规划记录和咨询记录由 C 负责。

留学规划不占底部 Tab，从首页“规划”功能入口进入，完整多步骤规划由 C 负责。

AI 规划和签证查询入口显示“功能建设中”。它们不创建空白页面、不伪造结果、不请求敏感权限。

导航使用原生页面栈，详情页保留可预测返回行为。请求中断或页面隐藏时应取消无需继续的读取请求，避免旧响应覆盖新页面状态。

## 6. 小程序认证设计

### 6.1 正式登录流程

1. 小程序调用 `wx.login()` 获取一次性 `code`。
2. 小程序请求 `POST /api/v1/miniapp/auth/login`，提交一次性 code、设备会话标识和客户端版本。
3. 后端通过微信官方 `jscode2session` 接口交换 `openid`、可选 `unionid` 与 `session_key`。
4. 后端校验微信响应；`session_key` 不返回前端，也不写入日志。
5. 后端使用 `WECHAT_MINI_PROGRAM + openid` 查找外部身份。不存在时创建仅外部身份账号和绑定记录。
6. 后端签发随机访问令牌和刷新令牌。数据库只保存令牌哈希、账号 ID、过期时间、撤销时间和轮换关系。
7. 小程序将访问令牌通过 `Authorization: Bearer <token>` 发送；刷新令牌只发往刷新接口。

访问令牌默认 15 分钟，刷新令牌默认 30 天。刷新时旧刷新令牌立即失效并签发新令牌；退出、账号停用或检测到重复使用时撤销令牌族。所有认证失败均返回稳定错误代码，不把微信原始错误、AppSecret、openid、session_key 或堆栈发给客户端。

### 6.2 开发登录

正式 AppID 未到位前，通过认证适配层使用受限本地提供方。该提供方必须同时满足：

- 只在非 `prod` profile 可启用。
- 需要显式环境变量批准。
- 只接受配置好的测试主体，不接受客户端任意指定用户 ID 或角色。
- 生产启动检查发现本地提供方时直接失败。

### 6.3 账号互通

首次小程序登录创建独立外部身份账号。后续邮箱绑定必须要求用户登录现有邮箱账号并完成明确确认，再在事务中合并允许合并的数据。`unionid` 可用于辅助识别，但不能自动合并两个已有账号。

## 7. 后端数据模型

第一阶段新增 Flyway 迁移，最小模型如下：

- `miniapp_auth_tokens`：访问/刷新令牌哈希、令牌类型、账号、族 ID、签发/过期/撤销时间和版本。
- 扩展现有外部身份提供方和数据库检查约束，增加 `WECHAT_MINI_PROGRAM`，继续使用现有外部身份唯一约束；网站扫码登录的 `WECHAT` 身份保持不变。

收藏与规划属于后续并行任务，但契约统一为：

- `user_saved_items`：账号、资源类型、稳定资源 ID、创建时间，唯一约束防止重复收藏。
- `study_plans`：账号、状态（草稿/已提交）、版本、规划字段、创建/更新时间；版本字段支持并发更新。

PostgreSQL 始终是业务数据真源。Redis 只可用于短期限流或可重建缓存，不作为账号、收藏或规划的永久存储。

## 8. API 与请求边界

小程序统一请求 `https://yangdoujiao.com/api/...`，正式发布前在微信公众平台配置该 HTTPS request 合法域名。不得直接请求服务器 IP。

首批接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/v1/miniapp/auth/login` | 微信 code 换取小程序会话 |
| `POST` | `/api/v1/miniapp/auth/refresh` | 轮换访问和刷新令牌 |
| `POST` | `/api/v1/miniapp/auth/logout` | 撤销当前令牌族 |
| `GET` | `/api/v1/miniapp/account` | 返回最小账号与绑定状态 |
| `GET` | `/api/v1/universities/search` | 复用现有院校查询 |

请求层只接受受信任的预定义 origin，默认 8 秒超时，读取请求允许一次受控重试，写请求只有带幂等键时才能重试。错误归一化为 `validation`、`unauthorized`、`forbidden`、`rate-limited`、`unavailable` 和 `unexpected`，页面不得展示后端原始异常消息。

## 9. 状态、隐私与权限

小程序本地只保存：不透明刷新令牌、可丢弃缓存版本、语言预留值和非敏感界面偏好。访问令牌优先保存在内存，需要恢复时通过刷新令牌换取。不得缓存身份证件、成绩单、联系方式、咨询正文或申请材料。

头像和昵称默认为品牌头像与“微信用户”。只有用户主动选择头像、填写昵称并提交后才保存。首次需要采集额外个人资料时展示对应隐私说明和用途，不在启动时一次性索取无关权限。

院校和专业读取保持公开。收藏、规划、咨询历史和账号信息必须使用有效 Bearer 令牌，并在服务层校验资源属于当前账号。管理员能力不会通过小程序令牌自动开放。

## 10. 可靠性与错误处理

- 页面必须有加载、空、失败、离线和重试状态，禁止用“没有数据”掩盖请求失败。
- 登录失效时先尝试一次刷新；刷新失败后清除本地令牌并返回可理解的登录入口。
- 多次快速搜索取消旧请求，只有最新请求可更新界面。
- 写请求携带 UUID 幂等键；后端按账号、操作类型和幂等键去重。
- 图片失败显示统一占位，不改变卡片高度。
- 未完成入口返回明确状态，不发起虚假请求。

## 11. 测试策略

自动测试覆盖：

- 环境配置只允许批准的 HTTPS origin，生产环境拒绝测试登录。
- 登录、刷新、退出、令牌轮换、撤销和重复刷新令牌检测。
- 严格解析微信与后端响应，缺失/多余/错误类型字段失败关闭。
- 请求超时、401 刷新、429、5xx、离线和旧请求覆盖保护。
- 四个 Tab 注册、页面路由、基础状态组件和触控尺寸契约。
- 院校搜索真实 DTO 映射，错误响应不能变成空列表。
- 后端 Flyway、仓储唯一约束、权限边界和日志脱敏。

人工验收覆盖微信开发者工具与至少一台真机：首次登录、冷启动续期、退出、网络中断、刘海/安全区、系统大字体、图片失败和首页到院校列表的完整路径。

## 13. 协作边界

- A 维护 `miniapp` 基础设施、认证、请求层、设计变量、公共状态组件和合并规则。
- B 只通过已定义的 `services` 与公共组件实现首页、院校列表和院校详情，不自行创建第二套请求封装。
- C 只通过同一基础层实现专业详情、规划和个人中心，不在页面内保存敏感业务数据。
- U圈正式业务不夹带在 B、C 的页面 PR 中；先单独完成社区 API、审核和数据保留规格，再建立独立分支实施。
- 每个业务模块独立分支和 PR；接口契约变化先修改类型与测试，再通知 B、C 同步。

## 14. 第一阶段验收标准

1. `miniapp/` 可由微信开发者工具导入，并在测试配置下启动。
2. `首页`、`院校`、`U圈`、`我的`四个 Tab 与样板的品牌视觉一致，安全区、触控尺寸和主要小屏尺寸无截断；留学规划可从首页进入。
3. 测试登录与正式登录适配器边界清晰，生产无法启用测试登录。
4. 登录后可读取最小账号状态；退出后受保护请求立即失效。
5. 院校 Tab 使用真实 `/api/v1/universities/search` 数据，加载、空结果和失败状态互不混淆。
6. AppSecret、令牌、个人资料和真实测试账号未进入 Git、日志或客户端包。
7. 前端现有测试、后端相关测试、小程序类型检查/Lint/单元测试全部通过。
8. README 写明开发导入、环境配置、测试和体验版上传步骤。
