# 公开文章接口设计

**日期：**2026-09-22  
**状态：**待项目负责人审核

## 目标与范围

老板要求“语言、奖学金、留学项目、新闻”采用列表页，并通过文章展示内容。本阶段只建立这四个栏目的公开只读数据接口，不制作后台编辑器，也不代替负责人撰写或审核文章。正式资料未导入时，列表可以为空，不能为了填充页面发布虚构内容。

现有架构保持不变：PostgreSQL 是文章数据的唯一来源，Spring Boot 提供 `/api/v1` REST 接口，Next.js 后续通过接口读取。第一阶段不接入 Elasticsearch 或 Redis；文章量和访问量达到需要时，再依据实际数据评估缓存与搜索。

## 方案选择

使用一张 `content_articles` 表，以 `section` 区分四个栏目。审核状态、发布时间、固定链接和双语内容沿用同一套规则。相比每个栏目各建一套表，这避免重复的发布逻辑；相比接入 CMS，不会在资料尚不完整时提前引入编辑后台、账号和权限系统。

栏目代码与现有前端路由一一对应：

| 栏目代码 | 页面路径 | 含义 |
| --- | --- | --- |
| `language` | `/{locale}/language` | 语言 |
| `scholarships` | `/{locale}/scholarships` | 奖学金 |
| `programmes` | `/{locale}/programmes` | 留学项目，不等同于院校下的学位课程 |
| `news` | `/{locale}/news` | 新闻 |

## 数据模型

每篇文章包含内部 `id`、`section`、`slug`、`status`、`published_at`、`created_at`、`updated_at`。`slug` 限小写英文字母、数字和连接号，最长 180 字符；同一栏目内唯一。发布后的 `slug` 不随标题调整，以免已有链接失效。`status` 只取 `DRAFT`、`PUBLISHED`、`ARCHIVED`。三个时间字段使用带时区时间戳，公开时间按 UTC 时刻比较。

内容字段为 `title_zh`、`title_en`、`summary_zh`、`summary_en`、`body_markdown_zh`、`body_markdown_en`。中英文不要求同时存在，但至少有一种语言具备非空标题和正文；某种语言若填写正文，也必须填写同语言标题，反之亦然。摘要可以为空。后端不生成翻译，接口对缺失语言返回 `null`，由前端明确按已有语言展示原文。

另有可选的 `cover_path`、`source_name`、`source_url`、`author_name`。封面只接受经过审核、以 `/content/` 开头且不含 `..` 的站内资源路径；来源链接只接受 HTTPS。没有材料时保持 `null`，不补写来源、作者或封面。Markdown 正文作为文本返回，后端不拼接 HTML；未来前端渲染时必须避免直接注入未经净化的 HTML。

数据库约束保证栏目代码、状态和固定链接格式合法，并保证至少一种完整语言内容。`PUBLISHED` 必须有 `published_at`。发布状态只表示内容已获审核；若发布时间在未来，公开查询仍不可见。

## 公开接口

### `GET /api/v1/articles/{section}`

分页返回指定栏目的文章摘要，使用项目现有 `PageResponse` 结构：`items`、`page`、`pageSize`、`totalItems`、`totalPages`。`page` 默认 1，`size` 默认 12、最大 48；非法页码、页大小或会造成分页偏移溢出的组合返回现有格式的 400 校验错误。

列表只包含 `status=PUBLISHED` 且 `published_at` 不晚于当前时间的记录，按 `published_at` 倒序、`id` 倒序稳定排序。摘要项包含 `section`、`slug`、两个标题、两个摘要、`coverPath` 和 `publishedAt`，不返回完整正文。没有已发布文章时返回 200 和空分页，不回退到草稿或测试数据。

### `GET /api/v1/articles/{section}/{slug}`

返回同一公开范围内的单篇文章，包含摘要字段以及 `bodyMarkdownZh`、`bodyMarkdownEn`、`sourceName`、`sourceUrl`、`authorName`。不存在、尚未到发布时间、草稿或归档文章一律返回 404，不泄露其内容或状态。未知栏目同样返回 404。

所有响应保留现有 `X-Trace-Id`，错误使用现有 `ApiErrorResponse`，不返回堆栈或未发布正文。接口不提供写入、状态切换或草稿预览功能。

## 内容进入系统的方式

本阶段只准备数据库结构和只读接口。文章由项目组根据老板确认的资料整理、审核后，另行通过受控导入流程写入数据库；生产迁移不插入示例文章。后台编辑、图片上传、审核工作流和通知属于后续独立阶段，不在本次接口 PR 中顺手实现。

前端现有四个占位页可在接口合并后单独接入列表与详情。该前端工作要继续保持页面结构和固定按钮中英双语；文章数据只有一种语言时展示原文，不用机器自动补译。当前接口阶段不改动这些页面。

## 验收与测试

- Flyway 迁移在空库及现有 V1–V5 数据库上执行成功，不改动院校、学位课程和搜索表。
- 数据库拒绝无有效栏目、无标题正文、非法状态、重复栏目内固定链接，以及没有发布时间的已发布文章。
- 列表和详情仅返回已审核且到达发布时间的文章；草稿、归档和定时未到的文章不公开。
- 空列表、分页边界、稳定排序、未知栏目和未知 `slug` 均有测试。
- 双语字段缺失时保持 `null`，不自动翻译；Markdown 原样作为文本返回。
- 集成测试使用隔离的 PostgreSQL 测试容器；不依赖正式文章资料或本地开发数据库。

## 不包含

本阶段不做文章编辑后台、登录权限、搜索、评论、浏览量、Redis 缓存、Elasticsearch 索引、图片上传、自动翻译、自动发布任务或正式内容编写。这些需求若出现，应分别确认范围和审核规则。
