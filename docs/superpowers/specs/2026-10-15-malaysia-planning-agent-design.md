# 马来西亚留学规划 Agent 首版设计

日期：2026-10-15

面向中国大陆学生，以网站已发布的马来西亚院校和专业为范围，覆盖预科、本科、硕士、博士。采用单个受控 Agent：通过对话补全背景，调用真实数据与规则工具，生成有依据的规划，支持调整、确认保存和主动转顾问。

本文件供用户确认后进入实施计划。不会因确认设计而自动接入付费模型、部署、上传微信版本或发布功能。

## 1 已确认范围与排除项

- 界面为聊天、专业卡片和结构化规划结果，沿用小程序视觉体系。
- 不要求用户重新提供学校名单，不按合作关系限制首版候选范围。
- 不自动申请、付款、联系学校，不承诺录取，不输出录取概率。
- 不提供开放网络代理、任意 SQL、终端执行或任意 URL 抓取工具。
- 首版不上传成绩单、护照或研究材料，不新增文档解析子系统。
- 官网资料的采集与顾问核验是独立的数据维护流程；聊天 Agent 无权把网上内容直接发布为事实。
- 不训练自有模型，不为首版引入多 Agent、独立微服务或向量数据库。

## 2 使用流程

1. 用户进入规划，先看到服务范围、AI 辅助说明和信息处理提示。模型未配置或功能未开放时，不显示可点击但不可用的首页入口。
2. 收集目标层级、学历背景、成绩及计分标准、语言情况、专业意向、预算口径和入学时间；城市为可选偏好。
3. 根据层级追问真正影响结果的信息，每轮最多两个相关问题。允许回答未知或跳过；用户未确认的信息不得升级为事实。
4. 用户确认背景摘要，Agent 查询候选专业，调用条件核对和预算工具。
5. 首次展示最多五个候选，附推荐理由、已知条件、差距、待核实事项、费用及来源；可以继续查看其他候选。
6. 用户改变条件后生成新版本，保留旧版本，不悄悄改变用户的预算或目标。
7. 用户明确点击保存后保存规划；转顾问前展示将分享的背景与方案，由用户确认后进入现有咨询流程。

建议首版登录后使用持久化对话，复用现有身份认证；不为 Agent 增设独立账号。技术设计中的限额与默认值均为首版方案，不是已部署行为。

## 3 学生背景

| 目标 | 需要的差异化背景 |
| --- | --- |
| 预科 | 高中在读或毕业、课程体系、年级与科目成绩、英语水平 |
| 本科 | 高中、高考、预科或专科背景，学业成绩、先修科目，是否申请转学分 |
| 硕士 | 本科学校、专业、学历学位取得情况、均分及满分、语言，授课或研究偏好 |
| 博士 | 本硕背景、成绩、研究经历和方向、研究计划准备情况、语言 |

成绩保留原始值、满分和考试或学历体系，不直接把百分制换算为 CGPA。专升本、成人教育、跨专业、转学分等只有在明确招生规则支持时才给出确定判断，否则列为需顾问核实。

预算区分人民币或其他币种、每年或全程、是否包含生活费。未明确这些口径前不得输出“预算够用”。没有雅思成绩不自动推断不符合，也不推断允许免语言录取。

## 4 数据与证据

PostgreSQL 继续是事实来源，Elasticsearch 只用于检索候选，返回结果须按当前已发布状态重新校验。不得把搜索缓存当作最终招生依据。

复用院校、专业、学历、学制、费用、入学时间及详情栏目。新增招生证据与规则的结构化记录，而不是直接把介绍文本作为条件：

- 证据：专业 ID、事实类型、原文摘要、官方来源 URL、适用学生范围、适用入学季、核实日期、有效截止日、审核状态和核验者。
- 规则：学历体系、学历或学位条件、成绩标准、科目要求、语言总分及单项、组合条件、例外条件、依赖证据 ID 和规则版本。
- 费用：金额、币种、计费周期、适用学生、税费及包含项、证据；汇率保留数值和日期。
- 规则只有经过人工核验且证据有效才参与确定性判断。复杂规则无法结构化时返回待核实，不让模型自行解释成可执行门槛。

AI 生成介绍可辅助说明学习方向，但必须标记生成属性，不能用于招生资格、官方课程表、费用或截止日期判断。来源缺失、未核验、过期或互相冲突的事实不得生成确定结论。招生与费用证据默认超过 90 天进入复核状态；若学校明确有效期或入学季，则取更严格限制。

数据补全覆盖现有目录，但按批次核验发布，不要求所有专业齐全才能提供查询。公开范围内无充分证据的项目只能进入“待核实候选”，不能与已核实匹配混排为同一等级。

## 5 受控工具与架构

在现有 Spring Boot 模块化单体内增加 planningagent 模块，遵循 Controller → Service → Repository。模型供应商通过独立适配接口接入，密钥仅在后端管理；不绑定具体商业模型。

| 工具 | 输入与职责 | 权限 |
| --- | --- | --- |
| search_programmes | 经校验的马来西亚、层级、专业及偏好条件；返回有效专业 ID | 只读 |
| get_programme_evidence | 专业 ID；返回结构化事实、证据及缺项 | 只读 |
| evaluate_eligibility | 背景版本、专业 ID 和规则版本；返回各条件状态 | 只读、确定性 |
| calculate_budget | 已核实费用、周期、学制、汇率和用户预算口径 | 只读、确定性 |

保存规划和转顾问由独立的用户操作接口执行，不作为模型可自主调用的写入工具。工具身份从服务端登录会话取得，模型不能传入任意用户 ID。

模型提出的工具调用必须经过名称白名单、JSON 参数校验、权限检查和调用限额。每轮最多八次工具调用、一次模型格式修复，总处理时限 60 秒；超限停止并提供重试或转顾问。工具只返回必要数据，不把整库或完整聊天历史发送给模型。

首版使用持久化运行记录与短轮询 REST 接口，避免依赖长连接：创建会话、提交消息、查询运行状态、确认背景、保存方案、读取自己的方案、删除自己的会话。消息提交携带幂等键，同一会话串行处理；客户端离开后可重新获取状态。后台任务在单体内执行，使用数据库状态与租约识别超时，不新增消息队列。

## 6 结果约束

条件核对按项目和单项返回：符合已核实条件、明确不符合、需补充学生信息、招生要求待核实。确定不符合与未知情况可以同时存在，不能互相覆盖。只有所有必需规则均有证据且满足时，才能显示“符合已核实的申请条件”，并注明不是录取承诺。

适合程度与申请资格分开：先按条件状态分组，再按用户确认的专业、城市、预算偏好排序，稳定排序用专业 ID；不使用学校佣金或模型虚构分数。没有合适项目时如实说明，不强行凑五个。

费用按原币逐项展示。计费周期或学制不明时不给全程总价；生活费只有存在已核实范围或用户自定假设时才估算，并显示假设。不同币种只有已知汇率时合并。部分小计不得命名为留学总预算。

最终方案包括背景摘要、候选项目、条件判断与证据、费用口径、待办事项和准备时间安排。申请截止日与学校规定必须引用有效来源；一般准备建议须与官方期限分开标注。

模型输出采用结构化格式。后端验证专业 ID、证据 ID、数值与工具结果，前端用受控字段渲染卡片和预算；模型文字不能覆盖条件状态与金额。验证失败不展示未验证建议，改为提供已核实卡片和可重试提示。

## 7 保存与现有功能衔接

保留现有规划功能和存量数据，不将旧规划误标为 Agent 产物。新增会话、消息、背景版本、运行记录、方案版本、项目结果及证据引用的关联记录，方案可在“我的规划”中以独立类型展示。

会话工作记录与用户主动保存的方案区分。方案保存时记录背景版本、规则和证据版本、生成时间；重新查看时检查专业是否下架、事实是否变更或过期，并提示重新核实，不静默改写旧方案。

顾问衔接复用现有咨询能力，只在用户确认后携带选定项目和背景摘要，不默认分享完整聊天。提交幂等，重复点击不创建重复咨询；前端区分提交中、成功和失败。

## 8 隐私与安全

首版只收集规划所需教育背景，不主动要求身份证、护照、详细住址、联系方式或原始文件。模型请求不携带用户微信标识、手机号或真实姓名；用户自由文本中的这些信息在传出前脱敏。

使用前说明 AI 服务与第三方处理范围；实际模型供应商、处理地域、保存政策、成本限额及所需隐私披露必须在接入和上线前确认。不在本次设计阶段购买服务或传送真实用户数据。

所有会话、方案和删除操作按所有者鉴权。只记录脱敏的运行状态、耗时、调用数量与错误类别，不默认把全文或密钥写入日志。模型和检索内容均视为不可信输入，资料里的指令不得改变工具权限或触发外部操作。

建议默认未保存会话在最后活动 30 天后删除，保存方案保留至用户删除或注销；执行删除时连带清理关联数据，备份清理遵循项目保留策略。上线前需实现并验证清理机制，不能只写在隐私说明中。

首版不向未满 14 周岁用户开放 Agent；展示顾问咨询替代入口。其他未成年人的授权和数据处理要求纳入上线隐私检查。

## 9 异常与运行限制

- 模型不可用：说明规划暂不可用，保留已确认背景，提供已有院校查询与咨询入口，不伪造规划结果。
- 数据缺失或来源冲突：展示缺项，允许继续浏览候选，不自动放宽条件。
- 请求重试、超时或应用重启：运行进入明确失败或超时状态，同一幂等键不重复生成、保存或计作新请求。
- 建议初始每用户每日 10 次规划生成或重算，另设消息速率及全局成本上限；达到限制后可读历史方案。实际商业预算确认前只允许测试环境运行。
- 功能开关默认关闭；测试环境可以用模拟模型验证流程，但生产不能以模拟结果替代真实服务。

## 10 验收与发布门槛

1. 四个层级各至少五组固定测试背景，覆盖成绩临界值、不同计分制、无语言成绩、跨专业、资料缺失及不符合条件。
2. 每个结论均可追溯有效规则与证据；未知条件不会被判为满足，AI 生成介绍不会成为招生证据。
3. 费用验证每年、每学期、全程、缺失周期、多币种、税费、生活费假设；不存在重复计算或把部分小计当总额。
4. 假专业 ID、虚构来源、提示注入、越权会话、未确认保存、重复提交、调用超限和超时均有测试。
5. 修改背景会产生新方案版本，历史不被覆盖；保存及转顾问只在用户确认后发生。
6. 在小程序真机完成从对话、查项目、查看依据、调整、保存、重新进入到咨询的完整流程。慢网、断网和模型失败均有可操作状态。
7. 使用至少 20 个顾问复核案例做离线评估，严重错误为零：伪造招生条件、未知判符合、费用口径错误、越权或未经同意的写入。
8. 每个学历层级至少有一个经核验的完整示范项目可走通；其他项目明确标注证据不足。上线宣传不得暗示全库均已核验。
9. 完成真实供应商和费用审批、隐私与内容安全检查、服务监控、成本熔断及关闭入口验证后，才允许另行授权上线。

## 11 后续实施划分

先完成证据与规则基础及确定性工具，再实现单 Agent 编排和会话记录，最后接入小程序界面、保存和顾问流程。模型接入可先用适配器测试替身完成接口验证；真实供应商接入与上线是独立确认点。
