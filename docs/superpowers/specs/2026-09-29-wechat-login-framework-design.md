# 微信登录框架设计

**日期：** 2026-09-29
**状态：** 已确认，待实施

## 背景

官网已经完成邮箱、手机号、密码、PostgreSQL Session 和 HttpOnly Cookie 组成的真实账号体系。老板已确认需要增加微信登录，但公司目前还没有微信开放平台开发者资质、已审核网站应用、AppID、AppSecret 和正式回调域名。

本阶段只实现可安全启用的微信网站扫码登录框架。没有正式资质时，生产页面不显示微信入口，也不提供假二维码或模拟登录。

## 目标

- 为微信开放平台“网站应用”预留正式 OAuth 登录流程。
- 微信身份最终复用现有本地账号、Spring Security 和 PostgreSQL Session。
- 微信首次授权后必须绑定并验证邮箱或手机号。
- 配置不完整时关闭优先，不影响现有邮箱和手机号登录。
- 使真实微信资质到位后只需添加环境变量并进行回调联调，不再重写账号主流程。

## 不包含

- 本阶段不代替公司申请微信开放平台资质。
- 不接入公众号网页授权、小程序登录、微信支付或微信分享。
- 不实现 Google、Apple 等通用多平台 OAuth 框架。
- 不将微信昵称、头像等非必要信息写入本地账号。
- 不在数据库中长期保存微信 Access Token 或 Refresh Token。

## 方案

采用“可替换 Provider，生产默认关闭”的方案。业务服务只依赖统一的微信 Provider 接口；正式实现负责与微信开放平台通信，测试实现只在显式的 test profile 中使用。

生产环境必须同时满足开关开启、AppID、AppSecret、官网来源和回调地址合法，才对外报告微信登录可用。任何一项缺失时，微信入口保持关闭。

## 请求流程

### 可用性检查

登录页读取 `GET /api/v1/auth/providers`。响应只包含公开状态，例如微信是否可用，不返回 AppID、AppSecret、回调配置或其他内部信息。

微信不可用时，前端不渲染微信登录按钮。

### 发起授权

用户点击微信登录后，浏览器进入 `GET /api/v1/auth/wechat/start`。后端：

1. 验证微信功能已启用。
2. 规范化并验证站内 `returnTo`。
3. 生成高熵的一次性 `state`，与当前浏览器 Session、回跳地址和过期时间绑定。
4. 跳转微信官方授权页面。

### 处理回调

微信回调 `GET /api/v1/auth/wechat/callback`。后端校验 `code`、`state`、Session、过期时间和一次性使用状态，再通过 Provider 换取微信用户唯一标识。

- 已绑定：检查本地账号仍为可用状态，更换 Session ID，建立与现有密码登录相同的本地会话，再返回站内页面。
- 未绑定：在 Session 中建立短期待绑定状态，返回登录页的微信绑定步骤。此时还不是已登录账号。

### 完成绑定

- 已有账号：用户输入邮箱或手机号及密码，验证通过后绑定。
- 新账号：用户填写姓名、邮箱或手机号、密码，确认当前用户协议和隐私政策，完成联系方式验证后创建账号并绑定。

账号绑定完成前，不能访问受保护的会员功能。

## 数据模型

新增 `user_external_identities`：

- `id`：内部主键。
- `user_account_id`：关联本地账号。
- `provider`：第一版只允许 `WECHAT`。
- `provider_client_id`：标识微信网站应用，用于隔离不同应用下的用户标识。
- `provider_subject`：微信返回的用户唯一标识。
- `created_at`、`last_login_at`：绑定时间和最后登录时间。

数据库约束：

- `(provider, provider_client_id, provider_subject)` 全局唯一，防止同一微信身份绑定多个账号。
- `(provider, user_account_id)` 唯一，第一版一个本地账号只绑定一个微信身份。
- 用户账号软删除后保留必要绑定记录，但已禁用或已删除账号不能通过微信登录恢复使用。最终保留期遵循后续审批的隐私政策。

OAuth `state` 和待绑定身份保存在服务端 Session 中，不存入前端 localStorage、sessionStorage 或 URL 长期参数。

## 安全边界

- AppSecret 只能通过服务器环境变量或密钥管理服务提供，不返回前端、不写入数据库、不提交 Git。
- 日志禁止记录 AppSecret、Access Token、Refresh Token、授权 `code`、完整 `state`、Cookie 和 Session ID。
- `state` 使用密码学安全随机数，只允许使用一次，且在短时间内过期。
- 只允许预配置的 HTTPS 回调地址和官网来源。
- `returnTo` 只允许当前站点内的本地化路径，拒绝协议开头、双斜杠、反斜杠和其他可疑值。
- 授权发起、回调和绑定操作纳入限流与审计；审计值只保留非敏感结果、`traceId` 和不可逆标识。
- 微信登录成功后必须更换 Session ID，并复用现有 HttpOnly、Secure 和 SameSite Cookie 策略。
- 不信任微信昵称或头像作为本地实名信息。

## 配置

新增类型安全的微信配置，环境变量名称保持明确：

- `APP_AUTH_WECHAT_ENABLED`
- `APP_AUTH_WECHAT_APP_ID`
- `APP_AUTH_WECHAT_APP_SECRET`
- `APP_AUTH_WECHAT_CALLBACK_URL`

默认 `APP_AUTH_WECHAT_ENABLED=false`。生产开启时要求回调地址为 `https://yangdoujiao.com/api/v1/auth/wechat/callback` 或经明确审批的同域预览地址。

配置示例文件只保留安全占位值，预检脚本在功能启用但参数缺失时直接失败。

## 异常处理

- 功能未启用：返回明确的不可用状态，不生成授权链接。
- 用户取消、二维码过期、`state` 不匹配或微信服务异常：返回登录页并显示通用且可本地化的提示，不展示上游响应。
- 身份已绑定其他账号：拒绝操作，不泄露目标账号资料。
- 本地账号已禁用或已删除：不创建登录 Session。
- 网络或微信暂时不可用：对用户返回可重试的通用失败提示，内部日志保留 `traceId` 以便排查。

## 测试策略

实施遵循测试驱动，不需要真实 AppID 和 AppSecret。

- 迁移测试：表结构、唯一约束、外键和旧数据兼容。
- 配置测试：默认关闭，开启时缺少必要参数应失败，生产拒绝不安全回调。
- 授权测试：生成授权地址、一次性 `state`、过期、Session 绑定和重放拒绝。
- 回调测试：用户取消、错误响应、缺少 `code`、已绑定登录和未绑定转移。
- 绑定测试：旧账号密码确认、新账号联系方式验证、重复身份、禁用账号和并发唯一性。
- 会话测试：登录时更换 Session ID，退出、修改密码和注销账号后无法继续使用。
- 安全测试：开放重定向、非 HTTPS 回调、敏感日志、非预期 HTTP 方法、CSRF 边界和限流。
- 前端测试：未配置时隐藏入口，已配置时展示入口，上游取消和错误时显示双语提示，绑定流程不会误判为已登录。

正式资质到位后，再在 HTTPS 域名上执行真实授权、取消、过期、重复扫码、新老账号绑定和退出的浏览器验收。

## 上线门槛

微信入口只能在以下条件全部完成后开启：

1. 微信开放平台开发者资质审核通过。
2. “网站应用”已审核，并已获得微信登录能力。
3. `yangdoujiao.com` 的 HTTPS、回调域名和反向代理已验收。
4. AppSecret 已进入生产密钥存储，不在代码、文档和聊天记录中。
5. 用户协议、隐私政策、第三方登录告知和数据保留规则已经审批。
6. 全量自动测试、生产配置预检和真实微信浏览器验收通过。

## 资质到位后的最终配置

正式网站应用建议使用：

```text
官网：https://yangdoujiao.com
授权回调域：yangdoujiao.com
后端回调：https://yangdoujiao.com/api/v1/auth/wechat/callback
```

微信开放平台审核页面的实际字段、费用、材料格式和回调域规则可能调整，提交时以微信官方当前要求为准。
