# V4 课程筛选与院校搜索接口设计

- **状态：** 已确认
- **日期：** 2026-09-17
- **范围：** 后端搜索接口、筛选字典接口、Elasticsearch 院校聚合索引、可靠同步机制与自动化测试

## 1. 目标与边界

V4 为“按照专业搜索学校”提供后端能力。公开页面按院校分页，每所院校只出现一次，并返回最多三个真正满足全部条件的专业。

本阶段包含：

- `GET /api/v1/universities/search`；
- `GET /api/v1/catalog/filter-options`；
- Elasticsearch 院校文档与嵌套专业映射；
- PostgreSQL 到 Elasticsearch 的可靠增量同步；
- 搜索别名、学费计费周期和课程人民币总学费字段；
- 参数校验、统一错误响应、自动化测试和中文 API 文档。

本阶段不包含：

- 前端页面实现或改版；
- 老板正式 Excel 数据导入；
- 自动拼写纠错、模糊搜索和未经审核的同义词；
- 搜索结果缓存；
- 咨询表单；
- 微服务、Kafka、RabbitMQ 或其他新增基础设施。

前端接入由负责前端的同事完成。V4 保留现有旧接口，待前端完成迁移后再单独讨论下线。

## 2. 架构原则

项目继续采用模块化单体：

```text
Next.js
  → Spring Boot SearchController
  → UniversitySearchService
  → Elasticsearch
  → 院校级分页结果
```

正式数据和搜索同步流程：

```text
后台管理或数据导入
  → PostgreSQL 业务事务
  → 同一事务写入 search_sync_jobs
  → SearchSyncWorker
  → Elasticsearch 院校文档
```

PostgreSQL 是业务数据的唯一真实来源。Elasticsearch 只保存可重建的搜索投影。Redis 暂不缓存 V4 搜索结果，避免在索引更新之外再引入缓存失效问题。

后端继续保留清晰模块：

- `catalog`：国家、专业分类、学历层次、课程模式和语言；
- `university`：院校；
- `programme`：课程及其语言、入学时间和学费；
- `search`：索引投影、查询、别名解析和同步任务；
- `common`：分页、错误响应、日志和请求追踪。

## 3. 数据库变更

新增 Flyway V4 迁移，不能修改已经发布的 V1、V2、V3。

### 3.1 课程学费补充字段

`programmes` 新增：

- `tuition_fee_period`：原始学费的计费周期，允许值至少包括 `PER_YEAR`、`PER_SEMESTER`、`TOTAL_PROGRAM` 和 `UNKNOWN`；
- `tuition_total_rmb_min`：整个课程的人民币总学费下限；
- `tuition_total_rmb_max`：整个课程的人民币总学费上限。

总学费字段必须同时满足：

- 金额大于等于零；
- 最低值不能大于最高值；
- 资料不足时保持空值，不能把未知值写成零；
- 只有明确、可追溯的整个课程人民币总学费才参与筛选。

### 3.2 搜索别名表

`search_aliases` 保存：

- 原始别名；
- 规范化别名；
- 语言；
- 目标类型；
- 目标稳定代码；
- 审核状态；
- 创建和更新时间。

只有审核通过的别名可以参与公开搜索。别名不能硬编码在 Java 中，也不能自动猜测。正式别名由老板或数据负责人确认；虚构别名只进入测试环境。

### 3.3 搜索同步任务表

`search_sync_jobs` 至少保存：

- 院校 ID；
- 任务状态；
- 尝试次数；
- 下次可执行时间；
- 最后错误摘要；
- 创建和更新时间。

同一院校的连续待处理任务可以合并。错误摘要不能包含密码、个人资料或完整业务正文。

## 4. Elasticsearch 文档

每一条公开搜索文档代表一所已发布院校。其已发布专业使用 `nested` 类型嵌入：

```text
UniversitySearchDocument
├── id、universityCode、slug
├── nameZh、nameEn
├── countryCode、countryNameZh、countryNameEn
├── cityZh、cityEn
├── popular
└── programmes (nested)
    ├── id、programmeCode
    ├── nameZh、nameEn
    ├── categoryCode
    ├── studyLevelCode
    ├── courseModeCode
    ├── languageCodes
    ├── durationMonths
    ├── intakeMonths
    ├── tuitionTotalRmbMin、tuitionTotalRmbMax
    └── 学制、入学时间和学费展示文本
```

代码和筛选字段使用 `keyword` 映射；金额和学制使用数值映射；年月使用可排序的规范值；中英文名称使用适合全文搜索的 `text` 映射，并保留精确匹配子字段。

所有专业级条件必须位于同一个 nested 查询中，禁止把同一学校不同专业的字段组合成一次错误命中。`inner_hits` 返回最多三个满足全部条件的专业。

索引采用版本名称和别名。重建时先创建并验证新索引，再原子切换读写别名，避免重建期间中断公开搜索。

## 5. 搜索接口

### 5.1 请求

```http
GET /api/v1/universities/search
```

支持：

| 参数 | 规则 |
| --- | --- |
| `q` | 专业中英文名称、专业分类和已审核别名；最长 100 个字符 |
| `category` | 专业分类稳定代码，可重复 |
| `level` | 学历层次稳定代码，可重复 |
| `country` | 国家代码，可重复 |
| `mode` | 课程模式稳定代码，可重复 |
| `language` | 授课语言稳定代码，可重复 |
| `duration` | 正整数月数，精确匹配 |
| `intake` | `YYYY-MM`；课程任一入学日期在该月即匹配 |
| `tuitionMin` | 整个课程人民币总学费筛选下限 |
| `tuitionMax` | 整个课程人民币总学费筛选上限 |
| `page` | 从 1 开始，默认 1 |
| `size` | 默认 12，最大 48 |
| `sort` | V4 仅支持 `relevance` |

同一维度的多个值使用 OR，不同维度之间使用 AND。学费范围只要存在交集就匹配；总学费为空的专业在启用学费筛选时不匹配。

没有关键词和筛选条件时，返回至少包含一个已发布专业的已发布院校，热门院校优先，再按名称和 ID 稳定排序。有关键词时按专业相关度排序，相同分数再使用稳定字段打破并列。

### 5.2 响应

响应使用现有 `PageResponse`：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 12,
  "totalItems": 0,
  "totalPages": 0
}
```

每个院校结果包含：

- 院校 ID、slug、中英文名称；
- 国家和城市中英文名称；
- 热门状态；
- 匹配专业总数；
- 最多三个匹配专业；
- 专业中英文名称、学历层次、课程模式和授课语言；
- 学制、入学时间和学费展示信息。

接口同时返回中英文业务字段。缺少的语言保持空值，不能自动翻译。当前数据库没有正式授权图片，V4 不伪造图片地址，前端继续显示占位内容。

## 6. 筛选字典接口

```http
GET /api/v1/catalog/filter-options
```

该接口从 PostgreSQL 返回已发布的：

- 国家；
- 专业分类；
- 学历层次；
- 课程模式；
- 授课语言。

每项使用稳定代码和中英文名称，并按业务排序字段返回。前端不得继续把未批准的筛选值硬编码为正式数据。

## 7. 关键词与别名规则

关键词先执行以下规范化：

1. 去除首尾空格；
2. 将连续空格合并；
3. 英文匹配不区分大小写；
4. 空字符串按未输入关键词处理。

查询使用结构化 `match` 或 `multi_match`，禁止拼接 `query_string` 通配符，避免多词或特殊字符导致 500。

V4 支持正式名称、分类和已审核别名，不提供自动拼写纠错。自动模糊搜索、前缀搜索、搜索建议和“你是不是想搜索”安排在正式数据导入后的 V5，并以真实查询数据和中英文测试结果为依据。

## 8. 同步与重建

业务数据变更和同步任务必须在同一 PostgreSQL 事务中提交。`SearchSyncWorker` 获取任务后，重新从 PostgreSQL 加载该院校的完整公开投影，而不是根据零散变更直接拼装文档。

同步行为：

- 已发布院校：写入完整院校文档；
- 非公开或已删除院校：删除公开搜索文档；
- 失败：增加尝试次数并延迟重试；
- 达到上限：标记为失败，等待开发人员处理；
- Elasticsearch 恢复后：可以继续处理待同步任务。

系统还必须提供受控的全量重建能力，以便首次部署、映射升级或索引损坏时从 PostgreSQL 恢复。全量重建不是公开匿名 API。

## 9. 校验与错误处理

以下请求返回 `400 Bad Request`：

- 页码或页大小超出范围；
- 学制不是正整数；
- 入学年月格式错误；
- 学费为负数或范围颠倒；
- 筛选代码不存在；
- 排序方式不支持；
- 关键词过长；
- 单一筛选维度包含过多值。

错误响应使用项目现有统一格式，包含安全的字段错误和 `traceId`。服务器不能向客户端返回 Java 堆栈或 Elasticsearch 内部错误。

Elasticsearch 不可用时返回 `503 Service Unavailable`。不能把故障伪装为空结果，也不能临时切换到规则不同的 PostgreSQL 搜索。

合法但无匹配结果的请求返回 `200 OK` 和空分页。

## 10. 测试策略

V4 使用测试驱动开发。

### 10.1 单元测试

- 关键词规范化；
- 入学年月解析；
- 学费范围交集；
- 学制精确匹配；
- 参数校验；
- DTO 映射；
- 同步重试规则；
- 缺少翻译时保持空值。

### 10.2 PostgreSQL 集成测试

- V4 可从 V1、V2、V3 顺序升级；
- 别名唯一性和状态约束；
- 学费计费周期、金额范围和空值规则；
- 同步任务状态和重试次数；
- 外键和删除行为；
- 测试数据只进入 Testcontainers 临时数据库。

### 10.3 Elasticsearch 集成测试

- 只索引已发布院校和专业；
- 同维度 OR、跨维度 AND；
- 同一个专业满足所有专业条件；
- 一校一卡、每校最多三个匹配专业；
- 13 所院校分页为 12 加 1；
- 学费交集、空学费、多语言和多入学时间；
- 中英文名称和已审核别名；
- 无结果空分页；
- 搜索服务不可用时的 503。

### 10.4 Controller 与兼容性测试

- 正常请求 200；
- 非法参数和未知代码 400；
- 统一分页和错误格式；
- `traceId` 传播；
- 不暴露内部异常；
- 旧 `/api/search`、`/api/universities` 和 `/api/universities/popular` 在迁移期间继续工作。

## 11. 完成标准

V4 只有同时满足以下条件才完成：

- 全部自动化测试通过；
- GitHub CI 通过；
- 中文 API 和数据库文档更新；
- 不包含 `.env`、真实密码或老板未批准的正式数据；
- 独立组员完成 PR 审核；
- 虚构测试数据覆盖批准的筛选矩阵；
- V3 和旧公开接口没有回归；
- 前端同事可以按照稳定接口契约完成接入。
